Ref Usage Migration Plan
Confidence: Medium-High

Current issue
- Any function can mutate any ref, making hidden dependencies and brittle ordering.

Target pattern
- One game state object passed into systems.
- Systems produce deterministic state patches and events.
- Refs remain only as runtime storage at top boundary until migration completes.

Practical transition
1) Introduce a state facade object in Frame-Game-1 loop.
2) Adapt one domain at a time to consume facade, not raw refs.
3) Replace direct writes with returned patches.
4) Keep behavior parity checks after each extraction.
